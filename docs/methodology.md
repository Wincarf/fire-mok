# Fire Mok — Flood detection methodology (SAR)

Technical document of the water-detection pipeline and flood extent.
Audience: technical managers, scientific reviewers, judges.

> **Warning**: Fire Mok outputs are a *triage score* to support decisions,
> not an official civil-defense alert.

## 1. Data

| Layer | Source | Product | Access |
|---|---|---|---|
| SAR backscatter (historical) | Sentinel-1 | RTC gamma0, VV band, `sentinel-1-rtc` collection | Microsoft Planetary Computer STAC, no authentication |
| SAR backscatter (present) | NISAR | GCOV (HDF5, L-band) | ASF DAAC, requires Earthdata |
| Optical validation | Sentinel-2 | L2A (B03, B08, SCL) | Planetary Computer STAC |
| Context (false positives) | ESA WorldCover | 10 m, classes 50 (built-up) and 80 (permanent water), epoch 2021 | Planetary Computer STAC (`esa-worldcover`) |
| Terrain | Copernicus DEM | GLO-30 -> HAND (Height Above Nearest Drainage) | Planetary Computer STAC |
| Population | WorldPop | 100 m, 2020, CC-BY 4.0 (documented alternative: NASA SEDAC GPW v4) | data.worldpop.org (HTTP windowed reads) |
| Observed weather | Open-Meteo + NASA POWER | daily precipitation + soil moisture; POWER (MERRA-2) as an independent estimate | public APIs |

The two SAR sensors stay in **separate layers**: NISAR is L-band,
Sentinel-1 is C-band. We do not difference across them — different
frequencies respond differently to the same surface.

## 2. Anchor case: the May 2024 Guaíba flood

- **"Wet" scene**: `S1A_...20240511T084943_rtc` — May 11, 2024, flood peak,
  descending track 08:49, 100% AOI coverage.
- **"Dry" scene (baseline)**: `S1A_...20240604T084924_rtc` — Jun 04, 2024,
  recession, same track 08:49, 100% coverage.

**Documented ruling**: the Planetary Computer RTC collection has no
pre-May-2024 scene for this AOI (partial, not complete archive). We use the
recession image as the dry baseline — standard methodology when no
pre-event scene exists: `flood = water(after) AND NOT water(before)`, with
`before` = post-recession scene. This can **overestimate** the extent in
areas still flooded on Jun 04, and it is mitigated by requiring a valid
(non-nodata) pixel in the baseline.

## 3. Water detection

- Linear → dB conversion: `σ0_dB = 10·log10(σ0)` (nodata preserved).
- Water mask: `σ0 < threshold`. Default threshold **−17 dB** (VV), calibrated
  by the validation below and adjustable interactively in the app.
- Flood extent: `water(after) AND NOT water(before) AND valid(before)`.
- Speckle cleanup: removal of connected blobs < 25 px (≈ 2,500 m² at 10 m).
- **Context cleanup (WorldCover 10 m)**: the final extent excludes urban
  (class 50) and permanent-water (class 80) pixels. Urban surfaces flip
  bright to dark between scenes and fool change detection — they were the
  false positives documented in section 6; permanent water escapes the
  valid-baseline rule at coverage edges. Both masks are available as app
  layers (`permanent_water`, `urban`). A WorldCover download failure never
  blocks the build (the mask is context).

## 4. Validation (Sentinel-2 NDWI, stratified chips over the AOI)

References: S2 L2A scenes from May 2024 with cloud cover < 40%, **ranked by
temporal proximity to the SAR scene** (was: footprint overlap). NDWI > 0.15
with SCL cloud masking. Full report:
`data/reports/may2024_validation.md` (not versioned, generated by
`pipeline/scripts/validate_flood.py --chips 30`).

**Statistical design (upgrade over the 4-chip pilot):**

- **Stratified sampling**: 30 chips of ~5.5 km, half from the `flood`
  stratum (≥ 5% water pixels per NDWI) and half from the `dry` stratum —
  pooled metrics would be dominated by chips without water.
- **Per-class metrics**, not just raw agreement: confusion matrix
  (TP/FP/FN/TN), **F1, IoU and Cohen's kappa** per σ0 threshold, with a
  **95% bootstrap confidence interval** (chip resampling, 1000 iterations,
  fixed seed). Raw agreement inflates with class imbalance; F1/IoU measure
  the water that matters.
- **Nodata excluded on both sides**: pixels without SAR or optical data do
  not vote (previously, SAR NaN counted as "non-water" and inflated
  agreement).
- Per-stratum sub-tables in the report, with per-stratum CIs.

**Original pilot (4 chips, 2024 — numbers without CI, kept as historical
reference):**

| σ0 threshold | Mean agreement |
|---|---|
| −13 dB | 52.6% |
| −15 dB | 57.4% |
| **−17 dB** | **66.6%** |
| −19 dB | 76.4% |

### Honest reading of the numbers

- **Temporal mismatch**: the SAR scene is May 11; the S2 references are
  1–10 days later, with the flood already receding. The SAR *correctly*
  shows more water.
- **SAR detects more water than NDWI**: part is real receding water, part
  is the method's known false positives — saturated soil, smooth urban
  surfaces and radar shadows also have low backscatter. The latter two are
  now **cut in section 3**; saturated soil remains.
- **NDWI under-detects turbid flood water** (sediment-rich), so the optical
  reference is biased too.
- −19 dB scores higher agreement but under-detects useful area; −17 dB is
  the chosen compromise. The app slider lets managers explore this
  trade-off.

## 5. Municipal risk index

Triage score 0–1 per municipality, a weighted linear combination of four
normalized components (implementation: `pipeline/pipeline/risk.py`):

| Component | Source | Normalization | Weight |
|---|---|---|---|
| Max 7-day rainfall (larger of observed and forecast) | Open-Meteo archive + forecast; NASA POWER as cross-check | cap 300 mm | 0.30 |
| Soil moisture | Open-Meteo (soil_moisture_0_to_7cm) | cap 0.5 m³/m³ | 0.20 |
| Susceptible terrain | Cop DEM GLO-30 -> **HAND < 15 m** AND slope < 5° | area fraction | 0.25 |
| Observed flooding | SAR extent (section 3) | cap 15% of area | 0.25 |

Categories: `low` ≤ 0.25 · `moderate` ≤ 0.50 · `high` ≤ 0.75 · `critical` > 0.75.

**The rainfall component looks forward**: it uses the larger of the rain
observed over the last 7 days (archive) and the rain forecast for the next
7 days (Open-Meteo forecast). Forecast rain above what already fell is the
future flood driver; a missing forecast contributes 0. POWER (MERRA-2,
NASA) serves as an **independent check** of the same rain: mean bias and
maximum divergence between the two sources enter the features
(`power_vs_openmeteo_bias_mm`) and large divergence flags a data problem.

**Terrain via HAND**: the previous rule (`elev < 50 m`) confused floodplain
with any low region. HAND (Height Above Nearest Drainage, Rennó et al.
2008) is the elevation difference between a cell and the nearest downstream
drainage — the same altitude is flood-prone on the Guaíba valley floor and
irrelevant on a plateau. Dependency-free implementation (priority-flood ε,
D8, accumulation, pointer-doubling); the 15 m threshold is triage, not
hydraulics.

**Real population exposure**: exposed population sums the WorldPop 2020
(100 m) grid over each municipality's flooded pixels (count-preserving
density conversion), replacing the uniform-density assumption. Without the
grid (network without HTTP Range), the calculation falls back to the
uniform estimate and records the method (`pop_method`) in the output
GeoJSON.

Qualitative calibration against May 2024: Charqueadas (0.81) and Eldorado
do Sul (0.75) come out `critical`; Triunfo, Nova Santa Rita, Porto Alegre
and Canoas come out `high` — consistent with the disaster's real geography.
The index is triage, not prediction: weights and caps are fixed and
documented here, with no per-event automatic tuning.

### Method references

- Twele, A. et al. (2016/2018). *Unsupervised Rapid Flood Mapping Using
  Sentinel-1 GRD SAR Images.* IEEE TGRS. doi:10.1109/tgrs.2018.2797536 —
  threshold-based water detection on σ0.
- Clement, M. et al. (2018). *An automatic change detection approach for
  rapid flood mapping in Sentinel-1 SAR data.* Int. J. Appl. Earth Obs.
  doi:10.1016/j.jag.2018.05.023 — before/after differencing (our section 3).
- DeVries, B. et al. (2020). *Rapid Flood Mapping and Evaluation with a
  Supervised Classifier and Change Detection.* Remote Sensing.
  doi:10.3390/rs12132073 — validation against optical references.
- Rennó, C. D. et al. (2008). *HAND, a new terrain descriptor using SRTM-DEM:
  mapping terra-firme rainforest environments in Amazonia.* Remote Sensing of
  Environment. doi:10.1016/j.rse.2008.03.018 — basis of the HAND index
  (section 5).

canonical reference for the HAND descriptor.)

## 6. Known limitations

1. Fixed global threshold — no Otsu/adaptive per-scene method (roadmap).
2. No incidence-angle correction — RTC is already gamma0, which reduces
   the effect.
3. Urban and permanent-water false positives are **cut by WorldCover**
   (section 3), but WorldCover is the 2021 epoch: areas urbanized after
   that can produce false positives again; saturated soil remains a
   potential FP (it is real water in transition, not a bug).
4. The baseline is recession, not pre-event — see the ruling in section 2.
5. Effective resolution ~10–20 m: narrow flooded streets fall below the
   pixel.
6. WorldPop is 2020 and a *grid estimate*, not the 2022 Census; the sum
   over flooded pixels is approximate and preserves the spatial
   distribution, not a displacement count.
7. HAND with a fixed 15 m threshold is plain triage, not hydraulic
   modeling — depth and dike protection are not included.
8. The index remains calibrated qualitatively against a single event
   (May 2024); the multi-event backtest (e.g., the Sep 2023 Taquari flood)
   is the next step to test the weights' generalization.

## 7. Operations

- Automatic ingestion: `pipeline/scripts/update_latest.py` (daily cron/
  Actions) builds the extent of the latest scene against the same orbital
  pass baseline — the index and the app track the present, not just the
  anchor case.
- CI: `.github/workflows/ci.yml` runs the 96 Python tests + 20 vitest tests
  on every push/PR; `.github/workflows/update-data.yml` runs the daily
  ingestion.
- API in a container: `docker build -t fire-mok . && docker run -p 8000:8000
  -v "$PWD/data:/app/data" fire-mok`; `/healthz` reports available layers.

## 8. Reproducibility

```bash
cd pipeline
uv run python scripts/build_may2024.py            # downloads scenes, builds mask + polygons + preview (with WorldCover context)
uv run python scripts/validate_flood.py --chips 30 # stratified validation vs Sentinel-2 NDWI (F1/IoU/kappa + CI)
uv run python scripts/update_latest.py --dry-run   # ingestion plan for the latest scene
uv run python scripts/validate_nisar.py           # NISAR GCOV (requires Earthdata)
```
